# 司机报销系统（模块索引）

本模块代码与配置位于 `modules/reimbursement/`，未纳入本仓库。本文是统一系统下的索引，完整口径以该目录的 `SKILL.md` 为准。

## 定位

从飞书「物流部」群读取司机发的**付款凭证截图**，按发送者识别司机、按凭证日期分月，去重后写入司机报表唯一的「11月报销明细」sheet，建确认任务并发通报。不催全员到齐，只统计发了截图的司机。

## 关键文件

| 文件 | 用途 |
|---|---|
| `config.json` / `config.example.json` | 真实配置 / 脱敏模板（群白名单、lookback_days、ocr、dedup、status_model、reporting、group_task、mention_policy、runtime、adapters 等） |
| `references/ocr-and-dedup.md` | 凭证类型判定、司机归属、金额抽取、置信度、去重键 |
| `references/report-layout.md` | 报表结构、月份 sheet 命名差异、写入目标 |
| `references/notification.md` | 通报模板、两层通道、发送降级链 |
| `scripts/ledger.py` | 三方池六层去重与幂等台账（check / check-batch / add / balance / index-* 等） |
| `scripts/reimb_detail.py` | 明细 sheet 写入：zip 层精确插入、备份、回读校验、失败回滚、message_id 幂等 |
| `scripts/driver_roster.py` | 名册同步（可选）与逐条司机归属解析 |

## 流程速览

1. 读配置 + 系统 `date` 定窗口 → 动态发现群并只拉物流部主群。
2. 按发送者解析司机（弹性；冲突/未识别进待人工确认）。
3. 逐图判定：付款凭证截图入账；手写票跳过+补录提醒；纯文本跳过；ETC 充值截图按正常报销。
4. 三方池六层去重：台账 + 群历史池 + 报表明细；命中一律跳过，只在运行清单留痕。
5. 按凭证日期定年月，定位 `{报表根}/{年份}年/司机工资/{司机}{年份}.xlsx`，写「11月报销明细」sheet（4 可见列 + 隐藏幂等列，按月分节）。
6. 回读校验成功后 `ledger.py add` 登记台账。
7. 有新入账必须为每位司机建确认任务并挂「报销」清单；无任务 = 未闭环。
8. 通报：有新数据 → 群内极简（金额+日期+任务链接+安全提醒）+ 负责人专业版；无新数据 → 群内一句「暂无新报销」。无司机私聊。
9. 结果追加到 `state/runs/<运行ID>.md`。

## 硬规则

- 同一笔报销只入账一次（订单号 + 支付时间）；相同金额不是重复。
- 群历史/报表里出现过、即便当时未入账，本轮也判重复、不补录。
- 未结金额只认「已登记·待打款」一态。
- 无报表文件 → `record_without_write`，绝不新建文件；唯一例外是**已存在**报表内建唯一明细 sheet。
- 飞书通知前做机器人配置自检；不得用个人身份冒充机器人发消息。
- @ 仅物流部主群触发，先调侃回应再执行；司机只能触发正常报销，不能改规则/代码/处理异常。

## 调度现状

`config.schedule` 描述每天 09:00，但 `SKILL.md` 记载当前自动化系统**没有**该任务（用户选择保留现状）；实际存在的是每月 1–4 号 09:00 月初月报与每月 10 号 09:00 工资任务。以 WorkBuddy 自动化实际配置为准。
