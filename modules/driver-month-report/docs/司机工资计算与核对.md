# 司机工资计算与核对（模块索引）

本模块代码与配置位于 `modules/driver-wage/`，未纳入本仓库。本文是统一系统下的索引，完整口径以该目录的 `SKILL.md` 与 `references/` 为准。

## 定位

只有两个业务能力：**计算工资（compute）** 与 **核对工资（verify）**。输入准备（名册同步、运输单筛选、图片转录、规则反推与确认、样式抽取）与交付编排（表格渲染、待确认预览、确认闸门、逐司机私发、定时发起）服务于这两件事，不构成第三个能力。

不做：报销归集、运费结算、车贷/油耗/管理费/净利润核算、考勤、社保、个税、报表写入、绩效分析、司机管理。

## 固定顺序

```
输入准备 → compute → verify → preview → 发起人确认 → dispatch
                      ↑ BLOCK 即停      ↑ 硬闸门，定时不得代劳
```

- `compute`：按已确认规则逐行求值，Decimal 精度累加，输出明细 + 汇总 + 输入指纹。
- `verify`：独立路径重算 + 核对；`BLOCK` 禁止确认与私发，`REVIEW` 需发起人显式接受，`PASS` 才进闸门。
- `preview`：计算+核对+渲染+工资条+待确认预览+通知发起人；**绝不向司机发消息**，是定时任务终点。
- `confirm`：`gate.owner` 本人用口令确认；核对结论与输入/规则/结果指纹绑定，变化即失效，有效期默认 72 小时。
- `dispatch`：默认 dry-run；已核对 + 已确认 + 显式 `--no-dry-run` 才真发；一人一条，只含本人数据。

## 口径要点

- 规则须人工确认（`confirmed=true`），反推规则默认 `confirmed=false` 会被阻断；不用 `eval` 任意公式。
- 名册飞书优先（通讯录部门 + 群成员，排除群主/负责人），本地只补充；只算当月有运输单或报销的司机，有几个算几个，不铺零值行。
- 历史工资表汇总块只读「报销」作加项；`rules.json` 中 `source: "reimbursement"` 的调整项不参与计算，避免与报销数据源双记。
- 同一趟运输只能进一个启用来源，否则核对判重复并阻断。
- 绝不修改历史工资表、报销台账或原始输入文件；产物只写 `out_dir`。
- 只发飞书在册、`notify=true`、有效 `open_id` 的司机；缺 open_id/司机没到齐不是异常，不催办、不降级群发。

## 命令速查

```bash
cd modules/driver-wage
python3 scripts/payroll.py init --trip-file <运输单> --wage-dir <历史表> --template <模板> --out-dir config/local
python3 scripts/payroll.py validate
python3 scripts/payroll.py sync-roster
python3 scripts/payroll.py compute --month YYYY-MM
python3 scripts/payroll.py verify --month YYYY-MM
python3 scripts/payroll.py preview --month YYYY-MM --notify-owner --no-dry-run
python3 scripts/payroll.py confirm --month YYYY-MM --token <口令> --owner <发起人>
python3 scripts/payroll.py dispatch --month YYYY-MM --no-dry-run --channel feishu
python3 scripts/payroll.py status --month YYYY-MM
```

脱敏自检：`python3 scripts/payroll.py --profile example demo --month 2026-09`。
提交前自检：`make check-privacy`（仓库内不得出现真实姓名/金额/路径/open_id/chat_id）。
