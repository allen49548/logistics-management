## 一、状态口径：区分「报销完成 / 未报销」

司机一多，最容易吵的是「这笔到底给没给钱」。所有凭证先归入 `config.status_model` 四态之一，**只有一态算还欠的钱**：

| 状态 | 台账依据 | 计入未结 | 负责人专业版措辞 |
|---|---|---|---|
| 已报销 | `reimbursed=1`（负责人点完成确认任务后由 `group_task.py check` 标记） | 否 | 已打款 |
| **已登记·待打款** | 台账已登记且 `reimbursed=0 AND voided=0`（确认任务未完成） | **是（唯一）** | 待打款 |
| 需你补材料 | 低置信度 / 无日期 / 未识别司机 / 手写票 / 纯文本，**未登记台账** | 否 | 需补材料 |
| 重复·未加钱 | `ledger.py check` 三方池六层去重命中（台账/群历史/报表明细，含跨时重发） | 否 | 重复提交·未重复计算 |
| 作废 | `voided=1` | 否 | 不计入 |

**未报销 / 未结金额 = 仅「已登记·待打款」累计**，由 `scripts/ledger.py balance` 按司机分组输出。
其余状态金额**一律不进**任何未报销、待确认或合计——这条同时守住「手写票不把金额列入待确认」与「重复提交坚决不加钱」两条铁律。

**四态与滚动「我的未结」只出现在负责人专业版与台账查询里**；按极简口径，群内不展示四态、笔数、未结或环比，只写本次报销金额与日期。状态并未取消，只是不再塞给司机看。

## 二、两层通报原则（核心）

每轮生成**两类**内容，由 `scripts/notify.py` **一次调用同时发出**：

| 通道 | 接收人 | 内容 | 发送目标 / 参数 |
|---|---|---|---|
| 通道一 群内总览 | 物流部全体 | **一份极简总览**：只列本轮有凭证的司机，一行「姓名 ¥金额（日期）」＋合计＋一行小提示＋一句安全驾驶调侃 | 唯一白名单群 `oc_a7cce7faf20bd2e4f841c1cd94f9684d`，`--chat-id` + `--text-file` |
| 通道二 专业完整版 | 廖浩成（本人） | 按司机分节的四态、未结、环比、订单号尾号、原登记时间、任务链接、台账/清单路径、未写报表原因、未识别司机、新司机待指定报表说明 | 固定 `owner_dm_chat_id`，`--owner-text-file` |

- **只列本轮/本月实际发了付款凭证截图的司机**：0 笔司机不出现，也不写「没列到名字的…」零值提示。手写票、纯文本、重复提交都不构成一条统计行。
- 群内一行 = 一位有凭证的司机，一行只有**姓名、金额、日期**。
- 金额公开，但专业字段只在负责人私聊；**专业版绝不到司机群**。
- **没有司机私聊通道**：`config.reporting.per_driver_dm.enabled=false`。`notify.py` 对误传的 `--driver-dm-manifest` 做硬拦截，返回 `blocked=true`、`sent=[]`，**绝不调用 `--user-id` 发任何私聊**，也不产生 `missing_driver_dm` 名单。`driver_copy.py render --kind personal` 保留但标记 deprecated，流程绝不调用。
- **有新数据时两层缺一不可**；**完全无新数据时只发负责人私聊、不发群**（notify.py 加 `--skip-group`）。绝不允许「因为没变化就完全不通报」。
- 每轮必须带**一行时间边界**「统计：…｜打款截止：…」（旧铁律），但不展开解释；正文仍只有金额和日期。
- 安全驾驶调侃句**必带**，同一轮全队同一句，按 `run_id` 日期顺序 7 天一循环，轻松不训斥、不用 emoji。
- **不纠结全员到齐**：司机增减是弹性的；未匹配名册、缺 open_id 只作信息记录，绝不当异常、待办或催办理由。

## 三、防串群 / 绝不发司机私聊（硬性）

1. 群内发送目标只能是 `config.json` 的 `chat_whitelist` 键，且该条 `notify=true`。**当前只有「物流部」一个键**。
2. 发送前 `notify.py` 对群 chat_id 做**精确字符串比对**：不完全等于白名单键立即拒绝（退出码 2），**禁止按群名搜索、模糊匹配或「看起来像」的群**。白名单校验通过后才允许发任何一层。
3. `config.retired_chats` 中的停用群（周小毛报销 / 陈华胜报销）`notify=false`、`read=false`，不在白名单里，`notify.py` 直接拒绝。
4. **绝不向司机发私聊**：配置禁用时任何 `--driver-dm-manifest` 都被 `blocked`；`--user-id` 发送路径不会被执行。名册外用户、停用旧群、门店群（小黑瓶丹竹头店 / 小黑瓶福田店）、非白名单会话一律不发。
5. 幂等键：群 `reimb-<运行ID>-<chat_id 前 8 位>`；负责人私聊 `reimb-<运行ID>-<owner chat_id 前 8 位>`。避免重复运行刷屏。
6. 新发现的其他符合条件群首次只写 `notify=false`，不发群消息，只向 `fallback_dm_chat_id` 报告「发现新报销群，待确认」。
7. 按司机列金额**不等于泄露专业细节**：群内只写「司机姓名 + 金额 + 日期」，不得夹带订单号、文件名、任务链接、路径、四态或环比。

## 四、发送命令

底层飞书发送（由 `notify.py` 封装，不要手拼）：

```
lark-cli im +messages-send --as bot --chat-id <chat_id> --text - \
  --idempotency-key "reimb-<runid>-<chatid8>" --format json
```

**群内文案先统一渲染（不要手写，避免口径漂移）：**

```
# 取本轮调侃句
python3 scripts/driver_copy.py joke --run-id <运行ID>

# 渲染群内总览（data 结构见 driver_copy.py 文件头）
python3 scripts/driver_copy.py render --data <data.json> --kind group --out <群版.txt>
```

`data.json` 最少字段：`run_id / generated_at / window / due / rows[{driver,amount,dates}]`，
可选 `scope_label / group_name / issues / no_change_wording`。
**`rows` 只放本轮实际有付款凭证的司机**（`amount>0`）；0 笔司机不要放进去。
`dates` 用凭证 `pay_time`（无则 `receipt_date`）的 `YYYY-MM-DD`，渲染时自动变 `M-DD`、去重升序、最多列 4 天。

**日常归集 / 月初月报统一一次调用两层：**

```
python3 scripts/notify.py \
  --chat-id oc_a7cce7faf20bd2e4f841c1cd94f9684d \
  --text-file <群内总览.txt> \
  --owner-text-file <专业版.txt> \
  --run-id <运行ID>
```

`notify.py` 输出 JSON 含 `results.group / results.driver_dm / results.owner`、`missing_driver_dm`（恒为空）与 `errors`。
`driver_dm` 恒为 `blocked` 或「未提供」，只为兼容旧调用方保留；**不要**把它当异常，也不要据它催司机进群。

预校验（不真发）：任意调用加 `--dry-run`，可同时验证白名单与幂等键。
即使旧自动化 prompt 带上 `--driver-dm-manifest`，dry-run 与正式调用都只会返回 `blocked`，不会发私聊。

## 五、身份降级链（每级只试一次，不循环重试）

| 顺序 | 身份 | 说明 |
|---|---|---|
| 1 | `--as bot` | 「廖浩成's Feishu CLI」机器人已在物流部群内，群内通报与负责人私聊默认走这里 |
| 2 | `--as user` | 失败时回退到本人身份（当前授权多数情况不含 `im:message.send_as_user` scope，仅作兜底） |
| 3 | 降级私聊 | **仅群内通报**：`--as bot --chat-id <fallback_dm_chat_id>`，消息开头标注「群内通报失败，降级私聊」及失败原因 |

- **群内总览**：bot → user → 降级私聊（确保不漏报）。
- **负责人私聊**：bot → user；失败只记错误，不阻塞群内层。
- 发送结果（成功 / 跳过 / 失败原因）必须写进运行清单。群内三级都失败时把完整原因追加到清单末尾，不回滚已完成的写入。
- `driver_roster.py sync` 会报告群内机器人数量；机器人被移出群时群内通报自动降级到本人私聊，如需恢复群内直发须人工把机器人拉回群。

## 六、发送时机（有新增才发详细通报；重复提交不再推送）

> 以顶部 2026-11-16 20:08 / 20:21 口径为准（覆盖下方旧表格）。

**核心：只有「新入账」才发详细通报；重复提交（旧凭证）不推送；无新入账（含纯重复）群里只一句「暂无新报销」。**

| 情形 | 群内总览（通道一） | 负责人私聊（通道二） |
|---|---|---|

- 重复提交（dedup 命中）**不再进任何通报**，逐项「原登记时间 + 是否已报销」只进运行清单 `state/runs/*.md` 供审计（铁律「绝不重复计算」不变，只是不再推旧消息）。

## 八、月初月报（每月 1–4 号，上月报销金额汇总 · 按司机分类）

口径：**直接按台账 `driver` 分组**，与群白名单解耦，停用旧群的历史条目仍计入；
**只列当月实际发了付款凭证截图的司机**（不铺全员名册、不列 0 笔司机）；
按 `pay_time` 所属月统计上个月未作废条目，专业版按四态拆分 **已报销 / 已登记·待打款（唯一计入未结）**；
与再上一个月按司机做**环比**；每自然月只真发一次（`state/monthly_sent.json` 防护）。

发送同样走**两层、一次 `notify.py` 调用**；不生成个人月报、不生成 manifest；
清单保存两层渲染原文与发送结果。**群内版由 `driver_copy.py` 渲染极简版**，负责人版保持不变。
