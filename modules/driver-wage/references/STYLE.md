# 统一表格格式规范

需求里的「文字、背景、字体、颜色、模板统一」由 **`config/style.json` 单一来源**控制。
所有月份、所有司机、所有产出（汇总表、明细表、每人一份工资条）共用同一份规范，不再各表各异。

## 一、规范值（从真实历史工资表抽取并收敛）

| 项 | 统一值 |
|---|---|
| 字体 | `PingFang SC` 系列，11pt（原始文件混用 11/12pt、`Calibri`、`微軟正黑體`、`等线`） |
| 表头 | 黄底 `FFFFE699`、黑字、加粗、居中、细边框、行高 24 |
| 数据区 | 白底 `FFFFFFFF`、居中、细边框 `FFBFBFBF`、行高 20 |
| 合计行 | 黄底 `FFFFE699`、加粗、居中 |
| 标题行 | 绿底 `FF70AD47`、白字、加粗、跨列合并 |
| 强调色 | 绿 `FF70AD47` / 橙 `FFED7D31`（原始表用作特殊标记，统一保留为调色板，不滥用） |
| 金额 | `¥#,##0.00`，两位小数，Decimal 计算后写入 |
| 公里数 | `#,##0` |
| 日期 | `yyyy-mm-dd` |
| 结构 | 标题行 → 表头 → 数据 → 合计；冻结表头；表头启用自动筛选 |
| 列宽 | 日期 14.6 / 路线 45.7 / 司机 12 / 金额列 13–15 / 默认 14 |

原始报表里表头是否加粗、字号、字体、底色在各司机之间并不一致；「统一」意味着**收敛成一份规范，而不是保留差异**。若发起人另有指定模板，以指定模板为准（见下）。

## 二、产出物

| 文件 | 内容 |
|---|---|
| `工资表_<YYYY-MM>.xlsx` | `工资汇总` sheet（一人一行 + 合计）、`工资明细` sheet（全体逐行，含来源文件与行号） |
| `payslips/<driver>_<month>.xlsx` | 每位司机独立一份，只含本人逐行明细与本人合计 |
| `payslips/<driver>_<month>.txt` | 私发消息正文，只含本人金额与趟数 |

汇总表表头固定为：司机 / 月份 / 趟数 / 公里数 / 应发工资 / 报销 / 扣款 / 实发工资 / 规则状态。
明细表表头固定为：司机 / 日期 / 业务 / 车牌 / 趟次 / 路线 / 公里数 / 工资 / 来源 / 行号。
**每行可回溯到来源文件与行号**，争议时能定位。

## 三、换成发起人自己定的格式

```bash
python3 scripts/payroll.py extract-style \
  --template <发起人指定的模板.xlsx> \
  --out config/local/style.json \
  --header-row 1 --data-row 2 --total-row 13   # total-row 可省略
```

抽取内容：字体名 / 字号 / 粗体 / 字色、表头与数据区底色、合计行样式、对齐、列宽。
抽取是**只读**的，不修改模板。抽完可直接编辑 `style.json` 微调，例如改 `palette.header_bg` 或 `number_format.money`。

注意事项：

- 模板第一行应是表头；若模板有标题行，用 `--header-row 2`。
- 无填充的单元格在 xlsx 里是透明值，抽取时统一按白底处理，保证"背景统一"。
- 字体名带 `Regular` 之类后缀会被原样保留；跨平台使用时建议改成通用字体名并设 fallback。
- 修改 `style.json` 不会改变 `input_hash`（样式不属于计薪输入），因此不影响已确认结果；但会改变最终交付外观，建议在确认前定稿。

## 四、不得做的事

- 不得按司机分别套不同样式（会破坏"模板统一"）。
- 不得直接改写用户桌面上的历史工资表来"对齐格式"。
- 不得把其他司机的行出现在某个司机的工资条文件里。
- 不得在司机版工资条里出现订单号、台账路径、任务链接、规则诊断等专业人员字段。
